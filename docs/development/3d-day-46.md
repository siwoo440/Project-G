# 3D 46일차 | Windows 배포 후보와 최종 검증

---
## 빌드 구성

- 기준 코드 `507f5921f401ff157ab0ae51044cf48cbabb51bb`의 Assets·Packages·ProjectSettings를 Git에서 추출했다. Unity 6000.3.21f1에서 StandaloneWindows64와 일반 플레이어 옵션을 사용했다. 등록한 게임 씬 여섯 개의 시작은 `FlightMainMenu`다.
- 첫 시도에서 Windows의 긴 클린 작업 경로로 패키지 셰이더와 편집기 리소스를 가져오지 못했다. 같은 소스를 짧은 임시 경로에 풀고 다시 빌드했다. 정식 후보는 `Builds/Project-G-3D-Day46-Windows-x64`에 있다.
- 배포 압축은 118,252,892바이트, 항목 195개로 확인했다. SHA-256은 `1FE4D1919BD697878022F7AF01A8354E5F41624BA9B8C8017CA0FD789BEE1884`다. Unity URP의 D3D11 디버그 셰이더 벡터 변환 경고 1건이 남아 있다.
- 배포 후보 실행 시 압축을 풀어 데이터 폴더와 DLL을 옆에 두고 `Project-G.exe`를 연다. 원본에서 다시 빌드하려면 Unity Build Profiles의 Windows 64비트와 기존 등록 씬을 사용한다.

---
## 현재 검증 범위

- Windows 빌드 26300, Ryzen 7 9800X3D, RTX 5070 Ti에서 정식 후보가 Direct3D 12를 초기화해 1280×720 창을 열고 정상 종료함을 확인했다. 플레이 검증에는 압축 후보와 같은 게임 소스에 별도의 격리 자동 입력을 추가했다.
- 깨끗한 소스의 Unity PlayMode 90개가 통과했다. 동일 소스의 Windows 검증 빌드에서 1920×1080으로 본편 첫 웨이브에 진입한 프로세스를 제어된 강제 종료로 중단했다. 새 1024×768 실행에서 같은 파일의 중단 보상 150골드·결정 3개·리안 숙련도 10을 한 번만 복구했다. 이어서하기, 출격 안내원의 F 대화와 출격 선택지, 통제 피격 뒤 결과, 같은 리안 재출격까지 확인했다.
- 앞선 41~43일차에 PlayMode와 Windows 1920×1080·1024×768에서 마을 NPC, 자유 훈련, 보스 러시, 탐험 분기와 체크포인트를 확인했다. 45일차에 같은 PC로 탄막 128발의 변경 전후 성능을 비교했다.
