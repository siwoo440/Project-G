## 3. 실제 플레이를 막고 있는 제작 항목

현재 새 스토리 장면 프리팹은 생성·검수하지 않았다.
따라서 본편 메뉴는 시나리오를 열람할 수 있으나, 실제 연결이 유효하지 않은 임무의 시작 버튼은 준비 중 상태로 유지한다.

장면별 구조·호송·조사·연락·인계의 실제 이벤트 생산자를 연결해야 한다.
대사 읽음이나 F8 진행 요청은 이 물리적 조건을 대신 충족하지 않는다.

승인된 주민·마물·구조대·기술·운용·연락 인원의 전체 ID 명단, 실제 목적지와 도착 트리거, 아리아·리안의 개별 ID를 배치해야 한다.
명단 수나 주민 체력을 임의로 채우지 않았다.

보호 대상의 실제 중심·반경, 안전 항로·대피 구역·빈 퇴각 공역, 필수 관측 지점과 예비 지점을 제작해야 한다.
생성 도구의 반경 0, 비어 있는 명단·지점, 누락된 생산자는 검사를 통과하지 않는다.

현지 작업의 동력·설비·인원·영창·문양, 보고·양방향 ACK, 국소 봉쇄의 실제 절차와 결과도 현장 컴포넌트에 연결해야 한다.
시간 경과나 빈 목록만으로 자동 성공시키지 않는다.

선택 서브의 현재 세계 방문 진입은 해당 현장의 안전 휴식·방문·허가 조건 연결이 남아 있다.
본편 이후의 회상 열람은 읽음 기록만 바꾸며 전투·임무 보상을 만들지 않는다.

## 4. 다음 작업 순서

1. Unity 6000.3.21f1에서 런타임·Editor·시험 어셈블리를 컴파일한다.
2. 제작 도구로 장면 연결 초안을 생성하고 실제 이벤트, 보호 대상, 명단, 관측 지점과 공간을 연결한다.
3. 신규 29개 PlayMode 시험과 기존 회귀 시험을 실행하고 실패를 수정한다.
4. 아리아·리안 기본 장비로 필수 조우와 8장 전체 흐름을 플레이한다.
5. 실제 소요 시간·피격·남은 내구·실패 원인·재시도 횟수·프레임 시간을 기록하고 수치와 연출을 조정한다.

상세 제작 절차는 [Unity 장면 연결 안내](story-step4-authoring.md)를 따른다.
위 게이트를 마치기 전에는 전체 4단계 완료, 최종 난이도 확정, 배포 준비 완료로 표시하지 않는다.

## 6. 연결 API 사용 규칙

비동기 작업을 시작할 때 `FlightStoryEvidenceSignal.BoundRunId`를 보관하고, 결과를 보낼 때 `SetPresent(capturedRunId, present)`에 같은 값을 전달한다.
재시도 뒤 새 ID를 읽어 과거 작업을 새 시도의 증거로 바꾸지 않는다.

명단 출발 보고도 작업 시작 시 보관한 ID를 사용한다.
인계 시작·완료는 해당 작업의 `FlightStoryPhase`를 보관해 전달한다.
보고와 관측의 단계·경로·시퀀스·시각은 실제 현재 자료와 일치해야 한다.

관측은 0.25초 활성 임무 시계로 평가한다.
긴 프레임에서 빠진 중간 관측을 하나의 현재 값으로 소급 생성하지 않는다.
피격 무적은 별도의 연속 활성 시간으로 평가해 관측 틱 때문에 1초보다 빨리 끝나지 않게 한다.
